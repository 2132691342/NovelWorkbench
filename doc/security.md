# 安全设计

本文说明认证、授权、密钥、审计、登录防护、上传与部署边界。
安全目标：**账号由管理员分配、权限逐请求校验、密钥不出明文、关键动作可追溯。**

## 1. 认证模型

| 项 | 设计 |
| --- | --- |
| 登录方式 | 登录名或邮箱 + 密码 |
| 密码存储 | bcrypt（DefaultCost），API 永不返回 `password_hash` |
| 会话 | JWT HS256，默认 7 天，载荷含 `user_ulid` 与有效期 |
| 登出 | 令牌写入 Redis 黑名单，TTL 为令牌剩余寿命 |
| 账号禁用 | 每次请求检查用户状态，禁用后旧令牌立即失效 |
| 注册 | **不开放**；账号只能由管理员在用户管理创建 |
| 个人改密 | 必须校验旧密码；成功后发安全通知 |

### 1.1 登录失败处理

- 账号不存在、密码错误统一返回 `ERR_UNAUTHORIZED` 与「账号或密码错误」，不泄露账号是否存在。
- 禁用账号返回 `ERR_FORBIDDEN` 与「账号已被禁用」。
- 三种结果都写入 `login_logs`，记录账号、IP、UA、结果与失败原因。
- 登录日志写入失败只告警，不阻断登录。

### 1.2 令牌校验链路

```
Authorization: Bearer <token>
  → 解析签名与过期时间
  → 查 Redis 黑名单
  → 查用户状态（不存在 / 禁用 → 401）
  → 注入 user_ulid
```

## 2. 授权模型

### 2.1 权限码单一事实源

- 权限码登记在 `menus.perm_code`，页面行与动作行都可以承载权限。
- 角色 `roles.perm_codes_json` 保存勾选的权限码；`*` 表示全部权限。
- 导航树与权限目录都从菜单表推导，新增权限只需登记菜单。
- 接口侧用 `RequirePermMiddleware` 逐请求查库，角色变更立即生效。

### 2.2 权限码表

| 权限码 | 语义 | 收口范围 |
| --- | --- | --- |
| `*` | 全部权限 | 内置 admin 角色 |
| `system:user:manage` | 用户管理 | 用户 CRUD、重置密码 |
| `system:role:manage` | 角色管理 | 角色 CRUD |
| `system:menu:manage` | 菜单管理 | 菜单 CRUD |
| `system:perm:read` | 权限目录 | 权限目录查看 |
| `system:audit:read` | 审计日志 | 审计分页 |
| `system:loginlog:read` | 登录日志 | 登录日志分页 |
| `system:job:manage` | 任务中心 | 任务列表、重试 |
| `system:model:manage` | 模型供应商 | 供应商保存、删除、测试 |
| `system:usage:read` | 用量分析 | 用量总览 |
| `system:status:read` | 运行状态 | 依赖健康 |
| `system:setting:manage` | 系统设置 | 运行时配置 |
| `skill:manage` | 技能资产 | 技能与参考资料写操作 |

### 2.3 数据归属

- 项目是创作资源的隔离边界，所有创作表带 `project_ulid`。
- service 层统一 `mustOwnProject`：不存在返回 404，非本人返回 403。
- 通知、登录日志、个人资料按 `user_ulid` 隔离。
- 任务中心与菜单 / 用户 / 角色等管理接口按权限码收口。

## 3. 密钥与配置

| 密钥 | 存储 | 说明 |
| --- | --- | --- |
| JWT Secret | 环境变量 `NW_JWT_SECRET` | 同时用于模型密钥封存；生产必须随机长串 |
| 模型 API Key | AES-256-GCM 加密后入库 | 仅回显掩码；解密仅发生在调用瞬间 |
| 数据库 / Redis / RabbitMQ / MinIO | `.env` 注入 | 仓库不保存真实凭据 |
| 管理员初始密码 | `NW_APP_ADMIN_PASSWORD` | 仅用户表为空时生效；生产必改 |

规则：

- 配置文件中的敏感字段一律留空，靠环境变量覆盖。
- `.env` 已被 `.gitignore` 忽略；示例文件只放占位值。
- 日志禁止输出密码、令牌、API Key 原文；部署脚本过滤含 `password` 的行。
- 密钥轮换：更换 `NW_JWT_SECRET` 会使既有令牌与模型密钥失效，需要重新登录与重填供应商密钥。

## 4. 审计与留痕

### 4.1 审计日志

- 所有 POST 请求（除登录、登出、`/chat/send`）记录一条审计。
- 字段：操作者、登录名、动作码（路径去掉 `/api/v1/`）、目标类型、目标 ULID、IP、时间。
- 仅 `/api/v1/admin/` 路径读取 body 提取目标，body 上限 64 KiB，读后还原。
- 写入失败只告警，不阻断业务。

### 4.2 登录日志

- 成功、密码错误、禁用账号都记录。
- 用于排查撞库、异常 IP、离职账号尝试。
- 管理端按权限码 `system:loginlog:read` 查看，支持账号 / IP、结果与日期筛选。

## 5. 上传与内容安全

| 风险 | 控制 |
| --- | --- |
| 超大文件 | `NW_APP_UPLOAD_MAX_MB` 限制；服务端再次校验 |
| 非法类型 | 仅允许 txt / md / docx / pdf；扩展名与内容解析双重校验 |
| 路径穿越 | 对象键由服务端生成，不使用用户文件名作为路径 |
| 文档解析 | 纯 Go 解析 docx/pdf，不落地临时可执行文件 |
| XSS | 富文本编辑器输出按组件处理；后端只存文本 |
| 对象存储 | 原文私有桶，前端通过后端字节流预览 |

## 6. 传输与部署边界

- 对外只暴露前端入口端口（默认 14399）；后端 8080、PG 5432、Redis 6379、RabbitMQ 5672、MinIO 9000、Manticore 9308 只在内网或本机监听。
- 生产建议在入口前加 TLS 终止（云负载均衡或 nginx），禁止明文公网传输密码。
- CORS 当前允许所有来源以便前后端分离开发；生产若固定域名，应收敛 `AllowOrigins`。
- 方法白名单只允许 GET / POST / OPTIONS；删除通过 POST `/xxx/delete`。
- 容器以非 root 运行（镜像层 Alpine + 非特权用户），中间件凭据由编排注入。

## 7. 威胁与对策

| 威胁 | 影响 | 对策 |
| --- | --- | --- |
| 撞库 | 账号被猜解 | bcrypt、统一失败文案、登录日志、管理员禁用 |
| 令牌泄露 | 会话被冒用 | 短有效期可配、登出黑名单、禁用账号即时失效 |
| 越权访问项目 | 读到他人作品 | 每个创作接口校验 `project_ulid` 归属 |
| 越权管理 | 修改用户 / 菜单 | 权限码逐请求查库；前端路由守卫只是体验层 |
| 密钥泄露 | 模型额度被盗 | AES-GCM 加密、掩码回显、日志脱敏 |
| 恶意文件 | 解析漏洞 / 资源耗尽 | 类型白名单、大小限制、纯 Go 解析、异步索引 |
| 审计缺失 | 无法追责 | 写操作全量审计；登录全量留痕 |
| 任务毒消息 | worker 卡死 | 内部重试上限、失败落库并 ack、任务中心可重试 |

## 8. 安全运维清单

- [ ] 生产替换 `NW_JWT_SECRET`、`NW_APP_ADMIN_PASSWORD` 与全部中间件口令。
- [ ] 确认 14399 之外的后端与中间件端口未对公网开放。
- [ ] 配置 TLS 终止与安全响应头（HSTS、X-Content-Type-Options）。
- [ ] 定期检查登录日志中的异常 IP 与失败峰值。
- [ ] 定期检查审计日志中的高危动作（删除项目、改角色、重置密码）。
- [ ] 备份 PostgreSQL、MinIO 桶与 Manticore 索引配置。
- [ ] 离职账号及时禁用；禁用后旧令牌自动失效。
- [ ] 模型供应商密钥按季度轮换。
