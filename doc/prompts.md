# 提示词资产：流程域矩阵与工具

本文是系统内置 AI 资产的**设计与实现说明**：资产如何组织、每个流程域交付什么、编码如何对应界面与 `/命令`、
作者改动如何与出厂内容共存，以及工具（Tool）与提示词的分工。提示词本身的构造规则见 [ai.md](ai.md)，本文只讲资产层。

## 1. 组织方式：一个流程域 = 1 份身份提示词 + 2 份指令提示词

写作是一条流水线，每个环节要的东西不同：立项要判断，起草要产出，打磨要克制，质检要狠。
所以内置资产按**流程域**组织，而不是按"提示词长什么样"组织：

| 层 | 落库位置 | 回答什么 | 什么时候用 | 注入角色 |
| --- | --- | --- | --- | --- |
| 身份提示词 | `prompts`（`prompt_kind_code=system`） | 我是谁、我的底线、我绝不写什么 | 整个会话期间持续生效，可临时切换 | 系统级消息 |
| 指令提示词 | `prompts`（`prompt_kind_code=command`） | 这一次具体做什么、按什么格式交付 | 由 `/编码` 或界面按钮单次触发 | 系统级消息 |
| 工具 | `tools` | 用确定性计算补事实（体检、摘要、设定检索） | 由 `#编码`、关键词命中或管理端试运行触发 | 上下文块 |

一个域内身份提示词与指令提示词是配套的：身份定"以什么身份说话"，指令定"这一单活怎么干"。
配合上下文装配（当前章节、@引用、召回、角色卡、设定、历史、工具结果），一次请求就构成完整作业单。

**注入约定（硬约束）**：提示词与上下文一律作为**系统级消息**进入消息序列，用户在对话框输入的内容始终是**用户级消息**。
二者在消息列表里可区分，模型侧也能正确理解"约束"与"要求"的边界。

### 1.2 编码与前端入口的契约

`/continue`、`/polish`、`/summary`、`/deai` 四个编码被写作台与体检面板直接引用
（`frontend/src/views/Workspace/index.vue`、`ChapterCheckPanel.vue`），改编码等于改前端契约，必须同步改前端。
其余编码只在提示词库与 `/` 菜单出现，不构成硬编码依赖。

## 2. 工具：确定性事实，由模型自行取用

提示词是"让模型按格式写"，工具是"由服务端算出事实再交给模型"。二者互补：

| 场景 | 用提示词 | 用工具 |
| --- | --- | --- |
| 要产出新文本 | ✅ | — |
| 要核对门禁、统计、检索既有数据 | — | ✅ |
| 结果必须可复现、可解释 | — | ✅ |

内置工具全部是服务端纯函数 + 仓储读，不额外消耗模型调用：

| 编码 | 名称 | 依赖数据 |
| --- | --- | --- |
| `chapter_check` | 章节体检 | 正文 |
| `deai_scan` | 去 AI 味扫描 | 正文 |
| `chapter_digest` | 章节摘要 | 正文 |
| `character_scan` | 角色出场统计 | 角色卡 + 正文 |
| `foreshadow_scan` | 伏笔回收检查 | 伏笔钩子 + 正文 |
| `lore_lookup` | 设定检索 | 世界观设定 |

### 2.1 谁决定调用：模型，而不是命令

工具**不**由命令注入。`/` 提示词与 `@` 引用都不携带工具，`#` 手动点名入口也已移除：
对话开始前服务端把启用工具的声明（`ai.ToolSpec` → eino `ToolInfo`，function name 即工具编码）随请求下发，
模型据此自行决定调不调、调哪个、传什么参数。

一次往返的完整链路：

```
消息序列 + 工具声明 → 模型流式生成
  ├─ 只出正文          → 直接落库，done 事件带 tool_code_list=[]
  └─ 回 tool_calls     → 服务端执行 → tool 消息回填 → 继续生成（最多 4 轮）
```

四道防线防止模型在工具上打转：

| 机制 | 作用 |
| --- | --- |
| 单轮去重 | 同一轮里「相同工具 + 相同参数」只执行一次，其余复用首次结果 |
| 跨轮检测 | 相邻两轮的调用签名相同即判定原地打转，摘掉工具声明逼模型用已有事实作答 |
| 轮数上限 | `chatToolRoundLimit = 4`，超限后交回已有正文 |
| 失败降级 | 单个工具失败把原因写进 tool 消息，由模型自己说明，不中止对话 |

### 2.2 上下文补齐

模型看不到章节 ULID，因此服务端补齐工作区上下文：

| 参数 | 模型给了 | 模型没给 |
| --- | --- | --- |
| `content_text` | 用模型给的 | 无当前章时用当前章正文 |
| `chapter_ulid` | 用模型给的 | 有当前章时用当前章 ULID |
| `query_text` | 用模型给的 | 用作者本轮原话 |

结果作为 tool 消息回填给模型（不是上下文块）：模型能看到自己调了什么、拿到了什么，
下一轮据此作答，而不是被服务端预先塞进一段它没要过的「工具结果」。

工具由 `service/tool_service.go` 播种与执行，`ai/builtin_tools.go` 定义出厂内容与指纹；
作者可改名称、说明、参数与启停，改过即 `customized_flag=true`，代码升级不再覆盖；内置工具不可删。

## 3. 提示词的构造规则

内置资产不是自由散文，而是**带验收判据的作业单**。每份指令提示词遵循同一套写法：

| 要素 | 作用 | 落点 |
| --- | --- | --- |
| 身份边界 | 明确"这一单活不做什么"，防止越界改写 | 身份提示词正文 |
| 交付格式 | 规定输出的结构（清单 / 分镜 / 对照表 / 正文） | 指令提示词正文 |
| 验收判据 | 给出可检查的通过条件，而非主观形容词 | 指令提示词正文 |
| 禁止项 | 列出常见劣化写法作为反向约束 | 指令提示词正文 |

长度约束：单份指令提示词控制在 350–800 字（实测 371–679 字），身份提示词 190–500 字。
超长方法论拆成"指令 + @引用提示词"两层——正文保留判据与格式，参考资料作为可 @ 引用的提示词注入。
出厂内容蒸馏自 `~/.workbuddy/skills` 下的小说类技能（去 AI 味、活人感写作、番茄/七猫网文、拆书、质检、改编等），
只保留可执行的写作纪律，剔除依赖脚本、文件写入与多轮调度的部分。

`human-writing` 类的要求不写成角色包装（如"你是全网第一"），只保留可执行的写作纪律。

## 4. 量化门禁的实现位置

章节体检的规则不写在提示词里，而是写成可单测的纯函数 `ai/check.Analyze`：

| 检查项 | 阈值 | 级别 |
| --- | --- | --- |
| 字数 | < 1500 | warn |
| 破折号 | > 12 处 | warn |
| 零容忍词 | 命中即判 | block |
| 警示词 | > 3 次 | warn |
| 情绪命名（感到/觉得） | > 2 次 | warn |
| 裸对话标签占比 | > 30% | warn |
| 章末钩子 | 末 60 字无悬念标点 | warn |
| 段落长度离散度 | < 0.08 | info |

综合分 = 100 − block×25 − warn×8 − info×2；有 block 即 `不可发`，有 warn 即 `需修`，否则 `可发`。
同一函数被三处复用：`POST /chapter/check`（写作台体检面板）、`chapter_check` 工具（对话期由模型调用）、`deai_scan` 工具（词面部分）。

## 5. 版本与作者改动

- **指纹升级**：提示词带 `asset_hash_text`（sha256，算法见 `ai.PromptAssetHash`），启动播种时与代码资产比对；
  一致则跳过，不一致且未自改则覆盖，`customized_flag=true` 时一律不覆盖。
- **下线清理**：不在当前清单中的内置编码（身份与指令合并成一个编码集合）直接删除；用户自建提示词不受影响。
  同理，已下线的内置菜单（如合并掉的「技能管理」）在启动时按 `retiredMenuCodeList` 清理，避免导航指向不存在的页面。
- **编码不可变**：内置提示词的 `prompt_code`、`scope_code`、`prompt_kind_code` 均不允许修改，
  因为它们同时是 `/命令` 与前端契约的一部分。
- **编码命名空间**：`/` 触发词由写作台本地动作与指令提示词共享，动作编码（`help`/`clear`/`new`/`attach`/`copy`/`check`/`focus`/`snapshot`）
  在 `domain.IsReservedActionCode` 里保留，保存同编码指令提示词会被拒绝。
  本地动作不进入模型调用，只改界面或写作台状态；指令提示词以系统级消息注入。
  两者在弹层里按来源分组并标注「本地 / 注入」，作者不必猜哪条会消耗额度。

维护动作见 [modules.md](modules.md) 第 15 节与 [api.md](api.md) 的提示词章节。
