# 提示词资产：流程域矩阵与工具

本文是系统内置 AI 资产的**设计与实现说明**：资产如何组织、每个流程域交付什么、编码如何对应界面与 `/命令`、
作者改动如何与出厂内容共存，以及工具（Tool）与技能的分工。提示词本身的构造规则见 [ai.md](ai.md)，本文只讲资产层。

## 1. 组织方式：一个流程域 = 1 份档案 + 2 个技能

写作是一条流水线，每个环节要的东西不同：立项要判断，起草要产出，打磨要克制，质检要狠。
所以内置资产按**流程域**组织，而不是按"提示词长什么样"组织：

| 层 | 落库位置 | 回答什么 | 什么时候用 |
| --- | --- | --- | --- |
| 大提示词（档案） | `prompt_profiles` | 我是谁、我的底线、我绝不写什么 | 整个会话期间持续生效，可临时切换 |
| 技能 | `skills` | 这一次具体做什么、按什么格式交付 | 由 `/编码` 或界面按钮单次触发 |
| 工具 | `tools` | 用确定性计算补事实（体检、摘要、设定检索） | 由 `#编码`、关键词命中或管理端试运行触发 |

一个域内档案与技能是配套的：档案定"以什么身份说话"，技能定"这一单活怎么干"。
配合上下文装配（当前章节、@引用、召回、角色卡、设定、历史、工具结果），一次请求就构成完整作业单。

### 1.2 技能编码与前端入口的契约

`/continue`、`/polish`、`/summary`、`/deai` 四个编码被写作台与体检面板直接引用
（`frontend/src/views/Workspace/index.vue`、`ChapterCheckPanel.vue`），改编码等于改前端契约，必须同步改前端。
其余编码只在技能列表与试用入口出现，不构成硬编码依赖。

## 2. 工具：确定性事实，而不是又一次模型调用

技能是"让模型按格式写"，工具是"由服务端算出事实再交给模型"。二者互补：

| 场景 | 用技能 | 用工具 |
| --- | --- | --- |
| 要产出新文本 | ✅ | — |
| 要核对门禁、统计、检索既有数据 | — | ✅ |
| 结果必须可复现、可解释 | — | ✅ |

内置工具全部是服务端纯函数 + 仓储读，不额外消耗模型调用：

| 编码 | 名称 | 触发关键词示例 | 依赖数据 |
| --- | --- | --- | --- |
| `chapter_check` | 章节体检 | 体检 / 能不能发 / 过稿 | 正文 |
| `deai_scan` | 去 AI 味扫描 | 去ai味 / 太像AI / 机器味 | 正文 |
| `chapter_digest` | 章节摘要 | 摘要 / 总结这章 | 正文 |
| `character_scan` | 角色出场统计 | 出场 / 谁出场 / 人物统计 | 角色卡 + 正文 |
| `foreshadow_scan` | 伏笔回收检查 | 伏笔 / 回收 / 挖坑 | 伏笔钩子 + 正文 |
| `lore_lookup` | 设定检索 | 查设定 / 世界观 / 资料里怎么写的 | 世界观设定 |

触发方式三种：正文命中 `trigger_keywords`（每次对话最多 2 个，按排序号取前）、管理端「试运行」显式调用、
后续扩展的 `#编码` 显式指定。结果以「工具结果」上下文块注入（优先级等同技能参考资料），失败只告警不阻断对话。

工具由 `service/tool_service.go` 播种与执行，`ai/builtin_tools.go` 定义出厂内容与指纹；
作者可改名称、说明、触发关键词与启停，改过即 `customized_flag=true`，代码升级不再覆盖；内置工具不可删。

## 3. 提示词的构造规则

内置资产不是自由散文，而是**带验收判据的作业单**。每份技能模板遵循同一套写法：

| 要素 | 作用 | 落地位置 |
| --- | --- | --- |
| 身份边界 | 明确"这一单活不做什么"，防止越界改写 | 档案正文 |
| 交付格式 | 规定输出的结构（清单 / 分镜 / 对照表 / 正文） | 技能模板 |
| 验收判据 | 给出可检查的通过条件，而非主观形容词 | 技能模板 |
| 禁止项 | 列出常见劣化写法作为反向约束 | 技能模板 |

长度约束：单个技能模板控制在 800–1600 字。超长方法论拆成"技能 + 参考资料"两层——
技能保留判据与格式，参考素材作为可按关键词命中的资料块注入（单技能上限 4000 字符）。

`human-writing` 类的要求不写成角色包装（如"你是全网第一"），只保留可执行的写作纪律；
依赖脚本、文件写入、多轮调度的流程不进入提示词。

## 4. 量化门禁的实现位置

章节体检的规则不写在提示词里，而是写成可单测的纯函数 `ai/check.Analyze`：

| 检查项 | 阈值 | 级别 |
| --- | --- | --- |
| 字数 | < 1500 | warn |
| 破折号 | > 12 处 | warn |
| 零容忍词 | 命中即判 | block |
| 警示词 | > 3 次 | warn |
| 情绪命名（感到/觉得） | > 2 次 | warn |
| 裸对话标签占比 | > 30% | warn |
| 章末钩子 | 末 60 字无悬念标点 | warn |
| 段落长度离散度 | < 0.08 | info |

综合分 = 100 − block×25 − warn×8 − info×2；有 block 即 `不可发`，有 warn 即 `需修`，否则 `可发`。
同一函数被三处复用：`POST /chapter/check`（写作台体检面板）、`#chapter_check` 工具（对话期）、`#deai_scan` 工具（词面部分）。

## 5. 版本与作者改动

- **指纹升级**：技能/档案/工具都带 `asset_hash_text`（sha256），启动播种时与代码资产比对；
  一致则跳过，不一致且未自改则覆盖，`customized_flag=true` 时一律不覆盖。
- **下线清理**：不在当前清单中的内置编码连同其参考资料一并删除；用户自建资产不受影响。
- **编码不可变**：内置技能的 `skill_code`、内置工具的 `tool_code`、内置档案的 `prompt_profile_code` 均不允许修改，
  因为它们同时是 `/命令`、`#命令` 与前端契约的一部分。

维护动作见 [modules.md](modules.md) 第 15、16、17 节与 [api.md](api.md) 的技能/工具/档案章节。
